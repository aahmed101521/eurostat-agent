# Eurostat Agent

A provenance-first foundation for an AI agent that answers questions using European official statistics.

The project currently focuses on **Eurostat** and is being built from the deterministic data layer upward: dataset discovery, metadata resolution, exact data retrieval, provenance capture, deterministic computation, and only then LLM-based orchestration.

The central design principle is:

> **An answer without complete provenance is a failure.**

The system is therefore designed so that numerical values are retrieved and computed by deterministic tools rather than generated by a language model.

---

## Why this project?

Questions that sound simple in natural language often require several non-trivial steps when answered from official statistics.

For example:

> What was the population of Belgian women aged 20 in 2024?

A reliable system must determine:

1. which Eurostat dataset represents the requested concept;
2. which dimensions that dataset contains;
3. which official codes correspond to terms such as Belgium, female, and age 20;
4. which observations satisfy those filters;
5. which unit the observation uses;
6. when the data were retrieved;
7. when Eurostat last updated the underlying dataset;
8. and which transformations were applied before presenting the result.

The goal of `eurostat-agent` is to make this process explicit, reproducible, testable, and auditable.

---

## Design principles

### Provenance first

Every eventual statistical answer should be traceable to information such as:

* dataset code;
* exact dimension filters;
* unit;
* observation value;
* extraction timestamp;
* dataset update information;
* and serialized computation steps.

### Deterministic statistics

The language model is intended to act as a controller and reasoning layer.

It should **not** invent, estimate, or directly manipulate official statistical values when deterministic tools can perform those operations.

### Official sources

The project currently uses two complementary Eurostat interfaces:

* the **Eurostat Catalogue API** for dataset discovery;
* the **Eurostat SDMX 3.0 API** for exact statistical structure, codelists, and observations.

### Test-driven development

Core behavior is specified with tests before implementation wherever practical.

The repository uses:

* `pytest`;
* `Hypothesis`;
* `Ruff`;
* `mypy`;
* `pre-commit`;
* and GitHub-based quality checks.

## Dataset discovery architecture

```text
Natural-language dataset query
              │
              ▼
       search_datasets(...)
              │
              ▼
         DatasetIndex
              │
              ▼
 deterministic ranking
              │
              ▼
 ranked DatasetRecord results
```

The index itself is built from the official Eurostat catalogue:

```text
Eurostat Catalogue API
        │
        ▼
   CatalogueClient
        │
        ▼
 CatalogueSnapshot
        │
        ▼
   DatasetIndex
```

A `CatalogueSnapshot` preserves both the catalogue contents and snapshot-level provenance, including the official source URL and Eurostat catalogue creation date.

## Example: searching the Eurostat catalogue

```python
import httpx

from eurostat_agent.catalogue import search_datasets
from eurostat_agent.catalogue_client import CatalogueClient


with httpx.Client() as http_client:
    catalogue_client = CatalogueClient(
        http_client=http_client,
    )

    index = catalogue_client.get_index()

    results = search_datasets(
        "population by age and sex",
        index=index,
        limit=5,
    )


for result in results:
    print(
        result.record.code,
        result.record.title,
        result.score,
        result.match_type,
    )
```

The result is a bounded, deterministic shortlist rather than an unconstrained catalogue dump.

Search results retain structured metadata such as:

* Eurostat product code;
* title;
* product type;
* description;
* last update;
* last modification;
* available data range;
* approximate value count;
* and one or more catalogue hierarchy paths.

## Ranking philosophy

Dataset discovery deliberately uses deterministic lexical ranking before introducing semantic or LLM-based retrieval.

Current signals include:

```text
exact dataset code
        ↓
exact title
        ↓
normalized title
        ↓
title phrase
        ↓
description phrase
        ↓
catalogue path phrase
        ↓
majority title-token overlap
```

Additional deterministic tie-breaking considers:

* plausible observed-data freshness;
* title specificity;
* and dataset update information.

Projection datasets are prevented from receiving an artificial freshness advantage simply because their projection horizon extends far into the future.

This baseline provides an interpretable retrieval system that can later be evaluated against more sophisticated alternatives.

## Example discovery result

For a query such as:

```text

```

the current live Eurostat catalogue ranking places the general Eurostat population dataset:

```text
demo_pjan
Population on 1 January by age and sex
```

among the highest-ranked candidates.

The ranking is derived from deterministic catalogue metadata rather than an LLM-generated dataset guess.

## Project architecture

The intended full architecture is:

```text
User question
     │
     ▼
LLM controller
     │
     ├── search_datasets(query)
     │
     ├── get_structure(dataset_code)
     │
     ├── resolve_code(dataset_code, dimension, text)
     │
     ├── fetch_series(dataset_code, filters)
     │
     └── compute(operation, frames)
     │
     ▼
Deterministic result
     │
     ▼
Provenance validation
     │
     ▼
Natural-language answer
```

The LLM layer is intentionally downstream of the deterministic statistical infrastructure.

## Planned deterministic tools

The target tool interface is:

```text
search_datasets(query)
get_structure(dataset_code)
resolve_code(dataset_code, dimension, text)
fetch_series(dataset_code, filters)
compute(operation, frames)
```

`search_datasets(...)`, structure retrieval, and deterministic series retrieval are already represented by the current implementation.

Code resolution, full provenance assembly, and deterministic computation are subsequent development stages.

## Scope

The current project intentionally focuses on:

* Eurostat;
* official published statistics;
* deterministic retrieval;
* deterministic computation;
* provenance;
* reproducibility;
* and evaluation of statistical-agent behavior.

The initial version does **not** aim to provide:

* forecasting;
* model fine-tuning;
* unrestricted general-purpose conversation;
* autonomous statistical inference;
* or multi-agent orchestration.

Those exclusions keep the statistical correctness and provenance problem tractable.

---

## Long-term objective

The objective is not merely to build a chatbot connected to Eurostat.

The objective is to build an **evaluatable statistical agent** in which every important transition from natural-language question to numerical answer can be inspected:

```text
question
→ dataset
→ dimensions
→ codes
→ observations
→ computation
→ answer
→ provenance
```

That separation makes it possible to measure where an agent succeeds, where it fails, and whether the final answer can actually be trusted.
